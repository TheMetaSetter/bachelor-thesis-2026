## 1. Main decision

Program THESIS completely first. After THESIS has stable code, configs, score exports, thresholds, and benchmark protocol, use that state as the reference contract for all baselines.

This avoids a common unfair setup: baselines and THESIS quietly using different splits, scaling, threshold sources, window-to-point rules, smoothing, or online warm-up handling.

## 3. Protocol to clarify before coding

These decisions should be fixed before implementation. They are config-level contracts, not hidden code behavior.

### 3.1 Offline benchmark protocol

Locked protocol:

- Split: use the same SMD train, clean validation, synthetic validation, and test split generated by the existing dataset config.
- Scaling: fit scaler on train only, reuse the exact scaler for validation/test.
- Window length: `20`, same as current benchmark configs.
- Clean validation, synthetic validation, and test are cut into non-overlapping windows.
- If a sequence has a leftover tail shorter than `window_size`, only the final tail-covering window may overlap with the previous window.
- For points covered by both the previous window and the tail-covering final window, average the anomaly scores from those windows.
- Offline training for THESIS: run O0/O1 two-stage training.
- Offline prediction: export raw point scores on test.
- Official offline point rule: use non-overlapping windows plus the tail-overlap exception above.
- Offline anomaly threshold: point-level threshold inferred from clean validation point scores only, default quantile `0.99`.
- Metrics: score-based metrics from raw point scores, label-based metrics from clean-validation threshold.
- Test labels: used only for metrics.
- Point adjustment: disabled unless applied to every method and clearly labeled.

Important detail: traditional ML methods do not have "pre-training" in the neural sense. In the offline benchmark they should be described as `fit/calibrate on train + clean validation, then score test`.

Plain explanation of the offline point rule:

- A model usually scores a window, not one isolated timestep.
- For official clean validation, synthetic validation, and test, we walk through the timeline by blocks of 20 points: `0..19`, `20..39`, `40..59`, and so on.
- If the last leftover piece has fewer than 20 points, we create one final full window ending at the sequence end. That final window is the only one allowed to overlap the previous window.
- If a point appears in both the previous window and the final tail window, its final anomaly score is the average of the two scores.
- This gives a mostly non-overlapping evaluation protocol while still scoring the leftover tail instead of dropping it.

ASCII view:

```text
clean_val / val_synth / test timeline

[0........19][20.......39][40.......59][60....79]
                                      [tail....end]
                                           ^
                                           only this final window may overlap

If a point is covered twice:

final_score[t] = mean(score_from_regular_window[t], score_from_tail_window[t])
```

### 3.2 Online streaming benchmark protocol

Locked protocol:

- Input stream: same scaled test sequence and same channel order as offline benchmark.
- Online windows: sliding windows.
- Score time: a point can be scored only when the window ending at that point is available.
- Warm-up: first `window_size - 1` points are marked as warm-up and excluded or separately reported.
- Point score aggregation: EWMA if THESIS uses EWMA.
- EWMA weights: `current = 0.9`, `previous = 0.1`, matching `full-spec-v2.md`.
- Online threshold: simulate clean validation as a stream, apply the same EWMA, then calibrate threshold at quantile `0.99`.
- No retroactive metric rewrite after online adaptation.
- Test labels: used only after predictions for metrics and optional demo overlay.

### 3.3 THESIS online trainable surface

Locked by `full-spec-v2.md`:

- Online trainable parameter group: only lightweight MLP projector `g_psi`.
- Frozen online: source encoder, continuous prototype bank, discrete codebook, reconstruction fusion head, reconstruction prediction head, classification path.
- A0 performs no optimizer step.
- A1 updates only `g_psi` with PNN reconstruction loss.
- A2 updates only `g_psi` with hard-old reconstruction loss or PNN reconstruction loss plus online contrastive regularizer.

The implementation must assert this at runtime and in tests.

Do not use full-test self-join as the main online baseline. If self-join variants are added later, label them explicitly as offline-only or partially comparable.

### 3.5 Baseline online adaptation policy

Locked protocol:

- CANDI and M2N2 use their native online adaptation logic, but they must consume the same stream, scaler, window size, threshold protocol, and metric implementation.
- STUMPY, KMeansAD, and IForest join the online benchmark as causal streaming scorers with frozen train-time fit/reference state.
- Traditional ML online runs should not update with test labels.
- If any traditional ML method gains a streaming update later, report it as a separate variant and apply the same non-overlap pseudo-normal admission policy as THESIS.

Reasoning:

- STUMPY/KMeansAD/IForest do not have the same kind of learned online projector as THESIS.
- If they update their reference set or fitted state directly from the test stream, the comparison becomes harder to interpret because test anomalies may enter the baseline state.
- Frozen streaming scoring is the cleanest main comparison: every method receives the stream causally, but traditional ML baselines keep the train-time state fixed.
- Adaptive traditional variants can still be interesting, but they should be a separate table.

### 3.6 Locked run budget and schedule

The main epoch budget is locked:

  expected_total_training_epochs: 30
  stage_a_multitask_epochs: 25
  stage_b_fusion_finetuning_epochs: 5

Do not create a larger default main budget unless a later experiment explicitly asks for it.

### 3.7 STUMPY implementation order

Plain explanation of the STUMPY choice:

- `STUMPY-ChannelAB-FrozenTrainRef` compares each test subsequence against train-normal subsequences. This matches the thesis benchmark idea: train/validation define the detector, test is only scored.
- Self-join STUMPY compares subsequences inside the same evaluation sequence. If run on full test, it can use future test context. That is acceptable only for an offline-only extra table, not as the main fair online comparator.

Recommended implementation order:

1. Implement `STUMPY-ChannelAB-FrozenTrainRef` first.
2. Verify the shared score/threshold/metric contract.
3. Add optional offline-only self-join variants only after the main benchmark is stable.

### 3.8 Synthetic anomaly quality policy

The 12-class taxonomy remains fixed:

```text
normal
spike
flip
speedup
noise
cutoff
average
scale
wander
contextual
upsidedown
mixture
```

The implementation should improve visibility through class-specific config controls, not by changing class names or label ids.

User-observed targets:

- `spike`: slightly stronger.
- `flip`: longer reversed segment.
- `speedup`: more visually different from clean.
- `spike` versus `flip`: reduce visual confusion.
- `cutoff`: clearer plateau or zero/hold behavior.
- `average`: clearer flattening.
- `scale`: stronger scale factors when too subtle.
- `wander`, `contextual`, `upsidedown`: modestly stronger.
- `mixture`: keep as-is first because it is already clear.

Recommended implementation:

- Add a synthetic intensity config profile for benchmark runs.
- Keep current defaults available as a legacy or conservative profile.
- Add visualization and numerical tests so each family changes enough points and enough magnitude to be visible without breaking the 12-class contract.

### 3.9 Pedagogical code quality policy

The implementation must be easy to read for a high-school student.

Required style:

- Prefer short files and short functions.
- Use explicit names instead of clever abbreviations.
- Keep each function responsible for one small action.
- Add small ASCII diagrams near new protocol-heavy modules.
- Use short comments only where they explain how the local code fits the bigger pipeline.
- Avoid hidden behavior in helper functions. If a helper changes protocol behavior, name it clearly.
- Use cute ASCII/kaomoji markers sparingly in section comments when they make the file easier to scan, for example `₍^. .^₎⟆`, `( ˶˘ ³˘)♡`, `₍₍⚞(˶˃ ꒳ ˂˶)⚟⁾⁾`, `⸜(｡˃ ᵕ ˂ )⸝♡`, `(˶˃𐃷˂˶)`.

## 10. Risks and mitigations

Risk: online THESIS gets too large and hard to read.

Mitigation: put one concept per file under `src/engine/online_tta/`, keep `src/models/online_adaptation.py` as the model boundary only.

Risk: traditional ML baselines accidentally get a different preprocessing path.

Mitigation: expose a shared sequence loader and scaler artifact, then require every baseline adapter to receive that object.

Risk: STUMPY is much slower on multivariate SMD.

Mitigation: implement `STUMPY-ChannelAB-FrozenTrainRef` first, log runtime by stage, add optional caps for smoke only, and keep self-join variants optional.

Risk: synthetic anomaly classes become easier but less faithful to the intended taxonomy.

Mitigation: add class-specific intensity controls, preserve the 12-class labels, and keep the previous profile available for comparison.

Risk: CANDI/M2N2 native adaptation is not equivalent to THESIS projector-only adaptation.

Mitigation: do not force them into THESIS internals. Instead, align stream, preprocessing, thresholds, metrics, and logging, and report their native update surface explicitly.

Risk: old benchmark configs conflict with new names.

Mitigation: keep old configs read-supported and add new offline/online benchmark folders as the active path.
