# Implementation Plan: Apply terminology ontology naming conventions to smoke W&B run names and identity fields

## Summary

Update the smoke W&B naming path so every generated smoke run uses `smk-<phase>-<method_or_variant>-<entity>-s<seed>`.

Keep `offline_pretraining_phase`, `online_tta_phase`, `offline_variant`, `online_variant`, method identity, stage identity, checkpoint identity, window identity, and protocol identity in canonical config or provenance fields.

Update the generators first, then update runtime callers that currently overwrite configured names, then regenerate derived YAML files and add exact-format tests.

## Request

Read the four staged project prompts, detect code lines that need modification for the terminology ontology naming conventions, and produce high-level phases, sequential stages, and indivisible atomic steps without implementing the code changes.

The selected smoke display format is `smk-<phase>-<method_or_variant>-<entity>-s<seed>`.

The selected examples are `smk-off-O0-e1_6-s8`, `smk-on-KA-A2-e3_9-s36`, and `smk-off-KA-e3_4-s6`.

## Current state

The current smoke inventory contains 508 YAML files and 508 explicit W&B run names.

None of the 508 names starts with `smk-`.

Existing generator paths emit `off-...-smoke`, `on-...-smoke`, or long experiment identifiers.

Several runtime callers replace the configured name with `build_wandb_run_name` before calling `ExperimentLogger`.

The current generic helper creates artifact-style `run-...` names and does not implement the selected smoke display contract.

Representative resolved configs lack canonical root `offline_variant` and `online_variant` fields.

## Desired end state

Every smoke config generated by an active generator contains `logging.use_wandb: true`, `logging.wandb_mode: online`, and a `logging.wandb_run_name` that matches the selected `smk-` grammar.

The display name uses `off` for `offline_pretraining_phase` and `on` for `online_tta_phase`.

The display identity uses `O0` or `O1` for `offline_variant`, `A0`, `A1`, or `A2` for `online_variant`, and `KA` for the explicitly selected `kmeans_ad` token.

The full canonical identity remains available in config, resolved config, W&B tags, W&B job type, metadata, checkpoint paths, or provenance.

Runners do not overwrite a valid configured smoke name with the older generic helper output.

## Scope

### In scope

- The shared smoke W&B display-name construction contract.
- Canonical offline and online identity fields required by artifact and run naming.
- Active benchmark and smoke config generators.
- Runtime callers that overwrite configured W&B names.
- Derived smoke YAML regeneration.
- Unit, generator, inventory, and runtime naming tests.

### Out of scope

- Renaming runtime compatibility fields such as scalar `raw_point_score`, `ewma_point_score`, and `prediction`.
- Renaming `verification_buffer` or `verification_entry`.
- Changing checkpoint filenames, output directory hierarchy, threshold schema, or metric semantics.
- Changing non-smoke W&B names unless the same code path must preserve them for compatibility.
- Choosing unapproved abbreviations for methods other than the selected `KA` token.

## Implementation approach

Use one small display-name helper with explicit phase, identity-token, entity, and seed inputs.

Keep display tokens separate from canonical identifiers and do not infer `offline_variant` from `experiment_variant` when canonical identity is unavailable.

Prefer a configured smoke name when it is already present and valid, so runtime callers do not silently replace a generator-owned name.

Update generator sources instead of hand-editing derived YAML files.

Use `KA` only for the explicitly selected `kmeans_ad` display token and preserve existing method tokens for methods without a confirmed short token.

## Phase 1: Establish the canonical identity and display-name contract

### Goal

Make the naming contract explicit in one code path and ensure canonical phase and variant identity is available before name composition.

### Changes

#### 1. Identity fields and validation

- **File:** `src/core/config.py`
- **Symbol:** `_validate_experiment_top_level_structure` and related config validation.
- **Change:** Allow optional root `offline_variant` and `online_variant` fields with the ontology domains `O0/O1` and `A0/A1/A2`.
- **Reason:** The ontology forbids silently substituting `experiment_variant` for `offline_variant` and requires cross-phase identity to be explicit.
- **Dependencies:** Config generators, artifact identity extraction, online benchmark runners, and config tests.

#### 2. Display-name helper

- **File:** `src/core/artifact_naming.py`
- **Symbol:** Add a focused smoke display-name builder next to the current artifact-name helpers.
- **Change:** Compose and validate `smk-off-...` or `smk-on-...` from explicit inputs without inserting stage or mode suffixes.
- **Reason:** The selected W&B name is a display label, not an artifact identity or a replacement for canonical config fields.
- **Dependencies:** Generator sources and runtime fallbacks.

### Verification

#### Automated

- [ ] Unit tests assert all three selected examples exactly.
- [ ] Unit tests reject missing phase, identity token, entity, or seed.
- [ ] Unit tests assert the helper does not use `experiment_variant` as `offline_variant`.

#### Manual

- [ ] Review the helper against both ontology files and the naming note.

### Risks

- Missing canonical identity could produce a misleading display name.
- Mitigation is fail-fast validation and preserving the full identity in config and metadata.

## Phase 2: Route all smoke naming through the contract

### Goal

Make active generators and runtime callers emit or preserve the selected smoke display name.

### Changes

#### 1. THESIS offline and online generators

- **Files:** `scripts/benchmarks/generate_smd_benchmark_configs.py`, `scripts/benchmarks/generate_benchmark_smoke_configs.py`, `scripts/benchmarks/generate_online_benchmark_configs.py`.
- **Change:** Replace legacy `off-...-smoke` and `on-...-smoke` construction with the shared helper and write canonical variant fields.
- **Reason:** These generators create the primary THESIS smoke matrix.

#### 2. Baseline generators

- **Files:** `scripts/benchmarks/generate_offline_benchmark_configs.py`, `scripts/benchmarks/generate_online_streaming_benchmark_configs.py`, `scripts/benchmarks/generate_remaining_smd_benchmark_configs.py`.
- **Change:** Build smoke names from phase, method or variant token, entity, and seed rather than from the long benchmark name or generic `run_id`.
- **Reason:** These sources account for the long legacy names in the smoke inventory.

#### 3. Runtime callers

- **Files:** `scripts/cli/train.py`, `scripts/cli/evaluate.py`, `scripts/experiments/run_online_adaptation.py`, `scripts/benchmarks/run_thesis_online_benchmark.py`, `scripts/experiments/run_two_stage_offline_pretraining.py`, `scripts/benchmarks/run_online_streaming_benchmark.py`.
- **Change:** Preserve a valid configured smoke name and only construct a fallback when the config does not provide one.
- **Reason:** Runtime overwrites currently bypass the generator contract.

#### 4. Special smoke entry point

- **File:** `scripts/run_direct_branch_routing_smoke.py`.
- **Change:** Replace the hard-coded legacy name with the selected smoke format while keeping direct-branch-routing in tags or metadata.
- **Reason:** The current string contains unrequested `direct` and `smoke` suffixes.

### Verification

#### Automated

#### Manual

## Testing strategy

Unit tests cover token validation and exact string composition.

Generator tests cover each active source of smoke configurations.

Runtime tests cover the final name passed to `wandb.init`.

Inventory tests cover all tracked smoke configurations under both config roots.

Existing artifact-name tests remain unchanged unless the canonical identity correction directly changes their intended contract.

## Migration and rollback

No output-directory or checkpoint-path migration is required.

Rollback consists of reverting generator and runtime naming changes and regenerating derived YAML from the previous generator revision.

Existing W&B runs remain historical records and are not renamed.
