## Research Question
Write the version of the model architecture described in the brainstorming notes.

## Summary
The DMTRL-LAF brainstorming note describes a multi-task CNN encoder in which each task-specific convolution kernel is generated from a shared low-rank factorization rather than learned as a separate parameter tensor. The central idea is to share a bank of basis kernels across tasks and let each task mix them through a small coefficient matrix. In the thesis setting under discussion, the natural task count is `T = 2`, namely reconstruction and anomaly-type classification.

This architecture is therefore an encoder-parameterization idea. It says nothing new about the anomaly injection pipeline, the metric pipeline, or the prototype-fusion mechanism by itself. The cleanest repository-level interpretation is that DMTRL-LAF would replace the internal parameterization of the simple CNN encoder while still respecting the repository contract that encoders receive `X in R^{B x L x D}` and emit a thesis-facing hidden representation.

## Detailed Findings

### Data Preparation
- The brainstorming note does not introduce a new dataset contract.
- The note does not define new preprocessing, windowing, scaling, or synthetic anomaly generation logic.
- Therefore, the data path remains external to the note and should be treated as inherited from the rest of the repository workflow.

### Modeling and Training

#### 1. Core encoder idea
- For each task `t`, a convolution kernel is generated by

  `K^(t) = sum_{k=1}^K L[:,:,:,:,k] S[k,t]`

- Here:
  - `L` is the tensor of shared basis kernels,
  - `S` is the task-specific coefficient matrix,
  - `K` is the latent factor rank,
  - `T` is the number of tasks.

- The convolution operator stays ordinary. Only the parameterization of the kernel changes.

#### 2. Example tensorization
- The note gives an example with

  `K^(t) in R^{3 x 3 x 64 x 128}`.

- With two tasks, the kernels are stacked as

  `K_stack in R^{3 x 3 x 64 x 128 x 2}`.

- Then all kernel axes except the task axis are flattened:

  `K_flat in R^{(3*3*64*128) x 2} = R^{73728 x 2}`.

#### 3. Low-rank factorization
- The note factorizes the flattened matrix as

  `K_flat ~= L_flat S`

  where:
  - `L_flat in R^{73728 x K}`,
  - `S in R^{K x 2}`.

- `L_flat` is then reshaped back into convolutional form:

  `L in R^{3 x 3 x 64 x 128 x K}`.

- This means the model stores:
  - one shared basis tensor `L`,
  - one task-mixing matrix `S`,
  instead of storing one full kernel per task.

#### 4. Forward pass
- The forward pass has two substeps:
  1. regenerate the task-specific kernel from `(L, S)`,
  2. apply ordinary convolution with that generated kernel.

- The note explicitly treats the generated kernels as intermediate computational objects.

#### 5. Initialization from single-task models
- The note does not start from random multitask factorization as its main story.
- Instead, it proposes:
  1. train separate single-task CNNs,
  2. extract their learned kernels,
  3. stack the kernels along the task axis,
  4. flatten the task-stacked tensor,
  5. factorize it,
  6. reshape the basis component,
  7. continue training in factorized multi-task form.

- So the intended pipeline is:

  `single-task pretrain -> kernel stacking -> factorization -> multitask fine-tuning`

#### 6. Loss view
- The note defines task losses abstractly:

  `L = sum_t L^(t)`

- In the two-task thesis use case, this corresponds at minimum to:

  `L = L_recon + L_cls`

- The note itself does not define prototype losses, contrastive losses, consensus losses, or fusion regularizers.

#### 7. Backpropagation view
- The note derives gradients in two stages:
  - first with respect to the generated kernel `K^(t)`,
  - then with respect to the true trainable parameters `L` and `S`.

- The critical conceptual point is:
  - `K^(t)` is used in convolution,
  - `L` and `S` are the true optimized parameters.

#### 8. Architectural interpretation under the thesis contract
- If translated into the repository language, the note reads most naturally as:

  `X -> DMTRL-LAF-based CNN encoder -> task-conditioned hidden representation(s) -> downstream thesis task pathway`

- The note by itself does not specify whether the factorized encoder should emit:
  - one shared hidden tensor,
  - or one hidden tensor per task.

- It also does not define how the factorized encoder should interact with:
  - continuous prototypes,
  - discrete prototypes,
  - task-specific fusion,
  - CKA-gated routing.

### Evaluation
- The brainstorming note does not define anomaly-detection metrics.
- It does not define thresholding rules, validation protocol, or reporting outputs.
- Its scope is only encoder-side parameterization and gradient flow.

## Pipeline Documentation
The architecture described by the note is:

`single-task kernels -> task-axis stacking -> flatten all non-task axes -> factorize into basis tensor L and coefficient matrix S -> regenerate task kernels -> ordinary convolution -> task losses`

So, hiểu nôm na thì, bản brainstorming không phải là prototype-fusion architecture hoàn chỉnh. Nó là một cách làm cho encoder CNN mang tính multi-task sharing ngay ở mức kernel weights.
