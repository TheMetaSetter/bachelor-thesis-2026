## goals of codebase
- goal 1 is to keep all code, documents and scripts within this codebase minimal as much as possible, with the assumption of re-writing parts of codebase is cheap and test-driven development is effective.
- goal 2 is to setup a strictly fair environment to experiment different baselines against the main method variants in both offline pre-training and online TTA phases.
- goal 3 is to have a high-school-student-friendly API to help everyone can import and use them easily in Jupyter notebooks.
- goal 4 is to ensure outputs can be uploaded each 30 minutes onto wandb and kaggle dataset which helps retain experimental results even in remote server crash.
- goal 5 is to help everyone can easily run ablation study on main method variants in both offline pre-training and online TTA phases, according to `/Users/conquerormikrokosmos/Downloads/LAPTOP MAC/IT/AI&DS/tsad-lib/documents/logs/2026-09-22/spec/smd-nine-baselines-local-smoke.md` in high-level view, and with more details in `/Users/conquerormikrokosmos/Downloads/LAPTOP MAC/IT/AI&DS/tsad-lib/src/tsad/matrix.py`.
- goal 6 is to help everyone can run experiments including a variety of methods and general and industrial datasets, with prioritize more on industrial datasets.
- goal 7 is to report VUS-PR, VUS-ROC, Affiliation F1-score, FPR, inference time per time-point, uncertainty estimation on validation set and on test set, in the same table layout as in bachelor-thesis-2026/reporting.
- goal 8 is to use fair backbone encoder between encoder-agnostic models. in this experiment, prioritize using simple 3-layer CNN backbone encoder in the same architecture as bachelor-thesis-2026/src/models. of course, students should be able to choose using different simple backbone encoders such as simple CNN backbone encoder, simple LSTM backbone encoder, simple Transformer backbone encoder, etc.
- goal 9 is to align all deep learning baselines to have total training epoch of 10 in wet runs, including all stages within training phase. for smoke runs, only use 10% of total training windows and use only 2+1 epochs for stage A and stage B in offline phase of MUSTARD method.
- goal 10 is to help students can easily measure performance of a method or a compare between methods using different metrics such as `VUS-PR`, `VUS-PR@FPR-budget`, `Affiliation F1-score`, `raw FPR`, `VUS-ROC`, `inference time per time-point`, `epistemic uncertainty on validation set`, `epistemic uncertainty on test set`, etc.
- goal 11 is to help students experiment easily with synthetic anomaly injection using 10 classes of synthetic anomalies from `RedLamp` paper and 1 class of normality. read legacy codebase `bachelor-thesis-2026/` for detailed implementation as source of reference.
- goal 12 is to use as little memory as possible when design artifacts and checkpoints saving, while ensuring reporting tables are accurate and encouraging fairness.
